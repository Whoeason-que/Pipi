# 消息发送与待发箱

输入框把两种操作分开：

- **引导**：会话正在工作时显示，向当前运行追加 steering。内核在下一次上下文组装时读取它，可以调整正在进行的任务；不取消正在执行的工具。
- **发送 / 排队**：空闲且没有待发消息时直接发送；运行中或已有待发消息时加入队列，等当前任务结束后逐条启动独立运行，不进入 steering。
- **延迟发送**：先设置等待分钟数，再点击「延迟发送」。时间从点击提交开始计算，到时且会话空闲才发送。范围为 1 分钟到 30 天。

Enter 发送或排队，Alt+Enter 引导，Shift+Enter 换行。输入法确认不触发提交。

待发箱显示每条消息、最早发送时间和队列状态，可以暂停、继续、逐条取消。未到时的定时消息不阻塞已到时的消息；已到时消息按提交顺序发送。暂停不改变设定时间，继续时已过期消息可立即发送。

停止当前任务会同时暂停它的待发箱；运行失败也暂停余下消息。失败前已开始的消息已经进入会话，不会自动重放。启动前的配置/契约错误则保留该条待发消息，并显示错误，修复后点击继续。取消只作用于待发消息，已经启动的任务应使用停止按钮。

队列与计时器由 Rust 宿主持有，桌面、Web、iPhone 使用相同的命令和事件。切换会话、卸载组件、刷新或关闭手机网页都不取消它。**宿主必须在线；待发箱只保存在当前宿主内存，退出/重启 Pipi 会清空未发消息。** 正式会话历史仍按原有 git 载体保存；临时测试的待发消息也只在当前宿主有效。

调度复用普通发送入口，使用该会话当时的模型与既有 Agent 配置/权限规则；待发消息本身不复制一份设置。会话压缩换 id 时，待发箱随同一个会话对象迁移。存在待发消息（包括暂停状态）时，不能归档、删除、分叉或释放该会话；先取消待发消息再操作。不同会话独立调度，没有全局运行上限。

## 实现与回归

宿主私有模块 `runtime/queue.rs` 调度待发箱，共用 `send_prompt` 的准备与运行入口。取出消息、预约运行与取消/停止都在原有 sessions 锁内串行完成。每条待发消息最多 64 KiB，每条会话最多 100 条；近期 256 个提交 id 保留幂等记录，以便响应丢失后用同 id 重试。

新增三个命令：`queue_prompt`、`cancel_queued_prompt`、`set_prompt_queue_paused`。`open_session` 快照包含 queue；`prompt-queue` 事件带 `agentName`、`sessionId`、`runId` 与独立递增的 queue revision。前端不在计时器里调用发送命令，也不把未发送消息伪装成 user entry。

自动回归覆盖当前任务/引导与后续消息的实际请求顺序、逐条运行、延迟不提前、会话隔离、到时消息不受未来消息阻塞、取消、停止/失败暂停、幂等提交、退出拒绝新消息、压缩换键，以及浏览器重连和迟到快照。

界面人工验收：运行中确认「引导」和「排队」分别可点；排队后确认消息只出现在待发箱，任务结束后才进入时间线；延迟发送后刷新页面核对待发箱；手机宽度检查按钮与取消/继续入口；停止任务后确认队列保持暂停。
