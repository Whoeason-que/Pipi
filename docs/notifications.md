# 桌面与 iPhone 通知

在「设置 → 通知」开启。桌面默认关闭；手机逐设备订阅，关闭一台不影响其他设备。
通知类型（回复完成、运行失败）是所有设备共用的设置。

## 桌面

使用 Tauri 官方通知插件，由 Rust 宿主直接投递。窗口可见且聚焦时不弹系统通知；
最小化、失焦或隐藏时提醒。开启桌面通知后关闭窗口会隐藏到托盘；彻底退出从托盘
选择 Quit Pipi。没有托盘时仍走原来的退出流程。

点击通知唤起窗口并打开对应会话；能否报告点击取决于系统通知服务。Windows 需要
安装后的应用验证，开发模式的图标/名称可能不同，而且点击 Action Center 内的
历史通知不保证回调。发送测试通知会绕过前台抑制与开关，便于检查系统是否允许显示。

## iPhone

1. 使用 iOS 16.4 或更新版本，通过固定的 HTTPS 域名打开 Pipi 远程网页。
2. 在浏览器分享菜单选择「添加到主屏幕」，然后从主屏幕图标打开。
3. 登录远程访问，在「设置 → 通知」点击「在这台设备开启通知」，允许系统授权。
4. 点击「发送测试通知」，然后锁屏或离开 Web App，验证通知显示与点击跳转。

不需要 Apple Developer 账号，也不需要另部署推送服务器。Pipi 宿主主动向浏览器
推送服务发送 HTTPS 请求；iPhone 使用 Apple 推送服务。手机页面关闭后仍可接收，
但 Pipi 所在电脑必须保持运行、联网。显示时机仍受系统通知权限与专注模式影响。
域名变更后需要重新添加和订阅；换浏览器、安装副本或设备也要各自开启。

HTTPS/Tunnel 用于打开界面、注册订阅和点击后的访问。推送本身不经过入站 Tunnel。
Cloudflare Access 登录过期时，点击通知可能需要重新认证；会话目标保留在 URL 中，
Pipi 等登录与 Agent 索引就绪后再打开。`sw.js`、manifest 和图标必须能作为同源静态
资源访问；Service Worker 不缓存 API、访问令牌、对话或文件预览。

## 数据与实现

- `settings.json.notifications`：桌面开关与两类通知的全局开关，兼容旧设置缺字段。
- `web-push.json`：VAPID 私钥和最多 32 台设备的订阅，首次显式开启时创建。
  原子替换，Unix 文件权限 `0600`；损坏、符号链接和超限文件拒绝使用，不覆盖密钥。
- 命令经过同一份 `pipi-core::commands`，订阅/退订/测试沿用 Web API 鉴权。
  私钥和其他设备的订阅不通过接口返回。桌面测试命令仅允许桌面来源。
- 通知仅携带 Agent 名称、状态及会话身份，不传对话、命令或 provider 错误。
  `web-push` 负责 AES128GCM 加密与 VAPID 签名，HTTP 复用 reqwest，禁止重定向。
  接受 Apple、Google FCM、Mozilla 的 HTTPS 推送端点；任意 URL 与内网端点拒绝。
- 用户 prompt 的运行入口等最终结果确认后才生成终态通知；主动停止、临时测试回复
  与手动压缩不产生完成通知。恢复性摘要错误不会把正常回复误报成失败。
  终态每轮一次，压缩后的通知带新 sessionId。
- 推送服务返回 404/410 时移除过期订阅；这台设备通过「重新连接通知」重新建立。
  其余失败不会删订阅或影响 Agent 运行。暂未加入持久发送队列和投递回执。

## 验证

自动回归覆盖终态判断、去重、重键、订阅隔离、私钥持久化/权限、无效端点拒绝、
实际加密消息与 VAPID 签名校验、Service Worker 可见通知及点击跳转、IPC wire。
桌面系统通知与 iPhone 的 APNs 投递仍需按上面的流程在真实设备验收。
