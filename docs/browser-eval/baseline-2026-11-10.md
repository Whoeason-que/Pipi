# 浏览器 Agent 评估基线：2026-11-10

题库 v1，Linux 图形会话；Pipi 真实运行时与 WebKitGTK 桌面浏览器后端；模型 `deepseek-v4.1-flash`。每题是新建 Agent `browser-eval-3512306` 的独立会话，只有浏览器工具。以下为一次运行，不能推断稳定通过率。

| 题目 | 结果 | 耗时 | 浏览器调用 | 工具报错 |
| --- | --- | ---: | ---: | ---: |
| 01 概览读取 | 通过 | 11.6 秒 | 2 | 0 |
| 02 多步导航 | 通过 | 15.1 秒 | 6 | 0 |
| 03 填写提交 | 通过，实际提交数据正确 | 19.9 秒 | 14 | 2 |
| 04 同源嵌入页面 | 失败：答案正确，但点击了未请求的诊断按钮 | 90.2 秒 | 33 | 2 |
| 05 跨源嵌入页面操作 | 失败：180 秒超时，未获得完成证据 | 180.2 秒 | 52 | 5 |

主要发现：

1. **多余动作**：第 04 题只要求查询。模型在同源 iframe 的快照中已拿到正确答案，之后仍访问独立诊断页面，猜测子页面地址，并点击了独立页面的“启动诊断”按钮。该测试按钮只操作本地虚构页面；独立打开时没有父页面接收诊断结果。本次无法据此判断其他模型的表现，但说明仅靠最终回答正确无法衡量任务边界。
2. **跨源 iframe 不可操作**：第 05 题的截图能看到 iframe 内按钮，快照却没有该按钮的引用；模型无法按坐标点击，尝试猜测地址、反复快照，直到超时。独立使用浏览器点击同一跨源按钮，父页面成功显示 `DIAG-314`，证明题目页面能够完成；这项独立核对使用的浏览器不是 Pipi 的 WebKitGTK。
3. **引用失效造成重试**：第 03 题在一次快照后连续填多个字段，前一次填入后引用全部失效，两次后续调用报错；模型重新获取快照后完成。第 04、05 题也发生过引用失效。需要保留失效保护，同时改善模型对操作与刷新关系的理解或设计更可靠的引用机制。
4. **缺少止损和可见性提示**：第 05 题对不可见的跨源内容进行了大量猜测和重复调用。当前快照没有明确说明跨源 iframe 被跳过，也没有可供模型控制的原生鼠标坐标操作；长时间无进展会消耗时间和调用额度。
